# Gannet 0.5.0 — New folders not on GitHub yet — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New Folder… on a workspace directory creates (or adopts) a folder, records the owner row it belongs to, and
shows it dimmed under that owner until GitHub lists its `origin`; it can be moved (drag and drop, Move to Owner…)
and forgotten.

**Architecture:** A small per-machine record (`src/newFolders.js`, in `machine.json` beside the workspace list)
holds `{ path, owner, account }`. `GannetTree.ownerChildren` turns this owner row's records into `newFolder` nodes
first, reconciling each against disk and GitHub's lists as it draws. The page gets a New Folder button, a dim icon
and drag and drop limited to new-folder rows onto owner rows; the extension owns the commands.

**Tech Stack:** plain JavaScript, VS Code extension API, the existing webview page; tests are node scripts
(`npm run -s test:offline`).

**Spec:** `docs/notes/101-gannet.md`, section "## New folders not on GitHub yet (0.5.0)".

The design holds every design decision; this plan holds build steps and code-level names only, and is deleted when
the work merges. If a decision changes during the build, change the design in the same commit.

## Global Constraints

- Gannet never writes inside a recorded folder: no `git init`, no remote, no `.git/config` change (also not when it
  becomes a checkout).
- Row copy: description `not on GitHub yet · <workspace or parent, ~ for home>`; with a GitHub origin not listed
  yet: `<owner>/<repo>, not on GitHub yet`. Adopt prompt: `<name> exists: it will be put under an owner`.
- Commands: `gannet.newFolder` (title "New Folder…"), `gannet.moveNewFolder` ("Move to Owner…"),
  `gannet.forgetNewFolder` ("Forget"); context value of the row: `newfolder`. All hidden from the palette.
- The record is written before the folder is added to the window.
- Version 0.5.0; Makefile `OLD_IDS` gains `seanahn.gannet-0.4.2`.

## Review Focus

1. Two recorded folders with the same name in different workspaces under one owner: two rows, unique ids, each
   expands to its own files.
2. A drag of any row that is not a new folder, or a drop on a row that is not an owner: nothing moves, no error.
3. A folder name with spaces, a leading dot or non-ASCII letters is accepted; `.`, `..`, `a/b`, `a\b`, empty are
   refused with a message, never created.
4. The origin names a repo listed under a different owner than recorded: the dim row disappears and the repo shows
   green under the remote's owner, never both.
5. A record whose workspace was removed from the list: the row stays, described with the folder's parent.

### Task 1: The record

**Files:**
- Create: `src/newFolders.js`
- Test: `test/newFolders.test.js` (add to `test:offline` in `package.json`)

**Interfaces:**
- Produces:
  - `createNewFolders({ memento }) → { list(): Rec[], add(rec): Promise, move(path, { owner, account }): Promise, forget(path): Promise, forRow(owner, account): Rec[] }`
    with `Rec = { path: string, owner: string, account: string }` (account = login). Key `gannet.newFolders`.
    `forRow` matches owner and account without case. `add` of a path already recorded replaces it.
  - `checkName(dir, name) → { ok: true, adopt: boolean } | { ok: false, message: string }` (pure, reads disk).
  - `module.exports = { createNewFolders, checkName, KEY }`

    `move('/w/a', {owner:'bpmn2', account:'seanahn'})` then `forRow('bpmn2','seanahn')` is `[/w/a]`;
    `forget('/v/a')` leaves one; `add` of `/w/a` again replaces, list length stays 1.

**Interfaces:**
- Consumes: Task 1 `createNewFolders`.
- Produces:
  - `new GannetTree({ …, newFolders })` (optional; absent = no rows).
  - Node `{ kind: 'newFolder', account, owner, rec, pending: string|null }` (`pending` = `owner/repo` of a GitHub
    origin not listed yet). `getChildren` of it = `diskDir(rec.path)`.
  - Item: label `basename(rec.path)`, collapsed, `contextValue 'newfolder'`, `iconPath ThemeIcon('github-alt', ThemeColor('descriptionForeground'))`,

    workspace, else `tilde(dirname(path))`), tooltip `checkoutLine({ path })`.
  - `nodeKey` of it: `n:<path>`.
  - `GannetTree.prototype.isListed(fullName) → boolean`: in any account's `pushed` or `knownList`, without case.

### Task 3: The page — New Folder button, dim icon, drag and drop

**Files:**
- Modify: `media/page.js`, `src/page.js` (CSS), `src/sidebar.js`
- Test: `test/page.test.js`, `test/sidebar.test.js`

**Interfaces:**
- Consumes: Task 2 row `contextValue 'newfolder'`; owner rows have `contextValue` `owner`, `account-gh`,
  `account-vscode`.
- Produces:
  - `workspacesHtml`: a `data-act="newFolder"` button (title `New Folder…`, a new `ICONS['new-folder']`) on every
    non-Missing directory, before Reveal.
  - `iconHtml`: colour `descriptionForeground` → class `dim` (CSS: `color: var(--vscode-descriptionForeground)`).
  - `rowHtml`: `draggable="true"` only on `newfolder` rows; `data-drop="1"` only on owner rows.
  - Page messages: `{ type: 'ws', act: 'newFolder', path }`; `{ type: 'move', id, to }` on a drop.
  - `GannetSidebar._handle`: `ws newFolder` → `gannet.newFolder` with `{ path }`; `move` → if `store.node(id)` is
    a `newFolder` node and `store.node(to)` an `owner` node → `gannet.moveNewFolder(node, target)`; else nothing.
  - Pure helper exported from `media/page.js`: `canDrop(dragRow, overRow) → boolean` (drag is `newfolder`, over is
    an owner row, and not the row's own parent owner id prefix).
