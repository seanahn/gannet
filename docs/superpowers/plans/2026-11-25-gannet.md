# Gannet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VS Code extension, `seanahn.gannet`, that shows the GitHub repos your accounts can reach as a tree, browses
their files lazily and read-only, and checks a repo out into a folder that is added to the workspace and pushes as the
account it came from.

**Architecture:** Small CommonJS modules with injected dependencies (`fetch`, a process runner, a memento, the `vscode`
API), so each is tested offline with stubs: a GitHub REST client, an accounts registry (gh + VS Code), state stores for
recent and local repos, a checkout queue running `git`, a token socket plus credential helper for VS Code accounts, a
read-only `gannet:` file system provider, and a tree data provider. `src/extension.js` wires them together.

**Tech Stack:** Plain JavaScript (Node 20 in the extension host), VS Code API ≥ 1.94, GitHub REST API over global
`fetch`, `git` and `gh` as child processes, Node's `assert` for tests (same style as Perch: one `node test/x.test.js`
script per module, printing `X OK`).

**Spec:** [docs/notes/101-gannet.md](../../notes/101-gannet.md)

The design holds every design decision; this plan holds build steps and code-level names only, and is deleted when the
work merges. If a decision changes during the build, change the design in the same commit.

## Global Constraints

- Extension id `seanahn.gannet`, publisher `seanahn`, MIT, repo `github.com/seanahn/gannet`, local `/git/gannet`.
- `extensionKind: ["workspace"]`; `engines.vscode: "^1.94.0"` (for `vscode.authentication.getAccounts`).
- No runtime dependencies (no Octokit, no bundler). Dev tooling via `npx --yes @vscode/vsce` only.
- github.com only. API base `https://api.github.com`, header `X-GitHub-Api-Version: 2022-11-28`.
- Never write a token to disk, a log, an error message or `.git/config`. Tokens live in memory only.
- Never change `gh`'s setup or machine-wide git config; the only git config Gannet writes is a checked-out repo's own
  `.git/config` (credential settings below).
- Settings: `gannet.checkoutFolder` (string, default `~/github`), `gannet.hiddenAccounts` (string array, default `[]`).
- Recent: at most 10 per account. Files over 10 MB (10 × 1024 × 1024 bytes) are not opened.
- Partial clones go to `<target>.gannet-partial`.
- Commits as `Sean Ahn <seanahn@youriris.com>`, each message ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Publishing, pushing to GitHub and installing are not part of this plan; they happen only when Sean asks.

## Review Focus

1. **A folder with more than 1,000 entries** (GitHub's contents API stops at 1,000): the tree shows those it got and a
   last item "More files — open on GitHub", never silently a partial list. Test: Task 1 (`listDir` reports
   `truncated`), Task 7 (the item).
2. **An empty repo** (contents API answers 409, or 404 on the root of a repo that exists): the repo expands to one
   item "Empty repository", not an error, and **Check out** still works. Test: Task 1, Task 7.
3. **Paths with spaces, `#`, `?`, `%` or non-ASCII** in folder and file names: browsing and opening work; each path
   segment is percent-encoded in API URLs and survives the `gannet:` URI round trip. Test: Task 1, Task 6.
4. **Submodules and symlinks in a listing** (`type` `submodule` / `symlink`): shown as items that do not expand; a
   submodule's click opens its repo on GitHub, a symlink opens as a file with its target. Test: Task 7.
5. **The same repo under two accounts:** once checked out from one, it shows **● local** under both; checking it out
   from the other only adds it to the workspace and leaves its push account alone. Test: Task 4, Task 7.

### Task 5: Token socket and credential helper for VS Code accounts

**Files:**
- Create: `src/tokenServer.js`, `bin/gannet-credential.js`
- Test: `test/tokenServer.test.js`

**Interfaces:**
- Consumes: `accounts.token(login)` (Task 2).
- Produces:
  - `startTokenServer({ dir, token: (login) => Promise<string> }) → Promise<{ path, close() }>` — listens on
    `<dir>/token-<pid>.sock` (mode 0600, `dir` created 0700), or `\\.\pipe\gannet-<user>-<pid>` on Windows. If
    `<dir>/token-<pid>.sock` would be over 100 bytes, `dir` becomes `<os.tmpdir()>/gannet-<uid>`. Protocol: one line
    in, `<login>\n`; one line out, `ok <token>\n` or `err <message>\n`; then close.
  - `writeShim({ dir, execPath, script }) → string` — writes `<dir>/gannet-credential` (0700, `#!/bin/sh`,
    `ELECTRON_RUN_AS_NODE=1 exec "<execPath>" "<script>" "$@"`), rewritten on every start so a VS Code update's new
    `execPath` is picked up; returns its path. The repo's helper string is `!"<shim>" <login>`.
  - `bin/gannet-credential.js <login> get`: reads git's stdin, tries each `token-*.sock` in its own folder's socket
    dir (passed via env `GANNET_SOCKET_DIR`, written into the shim), removes sockets that refuse connection, prints
    `username=<login>\npassword=<token>\n` from the first `ok`; none → writes to stderr
    `gannet: no VS Code window is serving <login> — open VS Code, or add the account to gh` and exits 1. Any action
    other than `get` exits 0 silently.

  socket file is removed and the next live one answers; no live socket → exit 1 with the message above; `store` exits 0
  with no output; the socket file mode is 0600.
