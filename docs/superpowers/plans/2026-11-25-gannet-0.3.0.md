# Gannet 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use trivialpowers:subagent-driven-development (recommended) or trivialpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Owner nodes instead of account nodes, a repo list cached on disk, several checkouts per repo with a green
Octocat, and a Workspaces panel that only lists directories.

**Architecture:** The state layer changes first: checkouts become a list per repo (`localRepos.js`), workspaces
become plain directories with a one-time migration (`workspaces.js`), and each account's full repo list gets a file
cache (`repoCache.js`). The repo tree (`tree.js`) is rebuilt on those, around owner nodes. Checkout naming and
resume move into `checkout.js`; `extension.js` wires the new flow and drops the workspace-file code.

**Tech Stack:** Node (CommonJS), VS Code extension API ^1.94, plain `node test/*.test.js` with the stubs in
`test/stubs.js`. No runtime dependencies after this plan.

**Spec:** `docs/notes/101-gannet.md`, section "Owners and workspace directories (0.3.0)". Where it and older
sections disagree, that section wins.

The design holds every design decision; this plan holds build steps and code-level names only, and is deleted when
the work merges. If a decision changes during the build, change the design in the same commit.

## Global Constraints

- Owner labels are the owner alone; an owner reached through another login has description `via <login>`.
- Green Octocat: `new ThemeIcon('github-alt', new ThemeColor('charts.green'))`; a repo only on GitHub keeps
  `new ThemeIcon('github-alt')`.
- Workspace descriptions on a repo are joined with ` · `, after `private` / `archived`; home shows as `~`.
- Folder names: first free of `<repo>`, `<owner>-<repo>`, `<repo>-2`, `<repo>-3`, …; never reuse a folder.
- Per-machine state stays in `<globalStorage>/machine.json` (keys `gannet.local`, `gannet.workspaces`,
  `gannet.pending`, plus the new `gannet.migrated`). The repo cache is `<globalStorage>/repos-<login>.json`.
- No token in any file, message or test output. No `jsonc-parser`.
- Commits by Sean Ahn, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A repo with two checkouts, one deleted from disk: the other still shows, single-checkout style.
2. Owner names in different case across lists (`C3-E` from one API, `c3-e` from another): one node.
3. A corrupt or half-written `repos-<login>.json`: treated as absent and fetched, never a crash.
4. One account signed out: its own node shows the error; the other account's owners are untouched.
5. Sean removes `~/github` from the list after upgrading: it is not added back on the next start.

Each has a test in the task that owns the code (tagged "Review Focus N").

### Task 4: The tree grouped by owner

**Files:**
- Modify: `src/tree.js`, `test/stubs.js` (add `ThemeColor`; `ThemeIcon(id, color)`)
- Modify (rewrite the account/group parts): `test/tree.test.js`

**Interfaces:**
- Consumes: Task 1 `checkoutsOf`; Task 3 `listOrgs`, `createRepoCache`, `merge(…, keep)`.
- Produces:
  - `new GannetTree({ vscode, accounts, clientFor, recent, local, cache, workspaces, home })`.
  - Node kinds: `owner { account, owner, own: boolean, org: boolean }`, `group { which:'recent'|'all', account,
    owner }`, `repo`, `checkout`, `entry`, `disk`, `info`, `error`.
  - `refresh()` — drops in-memory lists and marks every login stale: the next All repos open fetches again and
    replaces the file; until then root still reads owners from the file.
- Behaviour (all from the spec section "The tree is grouped by owner"):
  - root, per account: owners = own login, `listOrgs()`, owners of the pushed page (100), owners in the cached
    full list; deduped ignoring case (first spelling kept). Sorted by owner (ignoring case), then login.
  - an account whose pushed list fails (auth, rate) yields only its own node; that node's children are the error
    node. `listOrgs` failing means no orgs, no error shown.
  - owner item: label owner; description `via <login>` unless `own`; `id` `owner:<login>:<owner lowercased>`;
    state Expanded if `org`, or if `own` and the account has no orgs; otherwise Collapsed. `own` nodes keep
    contextValue `account-gh` / `account-vscode` and the 0.2.0 tooltip; others `owner`; icon `organization` for
    orgs, `account` otherwise.
  - owner children: Recent (`merge` with `keep = owner matches`) as repo nodes, then a group `all`.
  - group `all` children: the cached list (fetch, sort by name, `cache.set` when missing or stale) filtered to the
    owner; item label `All repos`, description the owner's count once known, tooltip `Fetched <toLocaleString>`.
  - Recent's `known` map comes from the cached list.
